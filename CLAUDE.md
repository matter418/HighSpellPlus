## Architecture (what matters)
- `src/main/` = Electron main (windows: client, settings, console, updater; modules: settings, screenshots, password store).
- `src/renderer/client/client.ts` = loader: POSTs to highspell.com/game, transplants the page DOM, fetches `client.<ver>.js`, caches it in IndexedDB, injects `document.client.get/set` (eval) 9 chars before the end, then boots `@ryelite/core` (`Highlite` class) and plugins.
- `@ryelite/core` (npm, node_modules; ALSO mapped via importmap in client.html to a jsdelivr CDN copy for plugins) = Reflector (acorn-parses the game bundle to find obfuscated class names by signature, saved to IndexedDB), HookManager, PluginManager, UI/panel/settings managers.
  - **HookManager.registerClass wraps EVERY prototype+static method of ~45 game classes** (GameLoop, GameEngine, EntityManager, MeshManager, SocketManager…) with a trampoline that allocs 2 arrays and loops all plugins per call. Real CPU cost but invisible while vsync-capped. Not fixed (lives in the npm package).
  - Plugin hook methods are named `<Class>_<method>` on the plugin instance; `document.highlite.gameHooks.<Class>` exposes the real classes; `this.gameHooks.EntityManager.Instance.MainPlayer` etc.
  - PluginManager.plugins includes placeholder entries for every plugin in the remote catalog (instance undefined) → "49 plugins" = 6 local + 16 installed + ~27 catalog rows. Not duplicates.
- Names to KEEP as-is (compat): `@ryelite/core`, `@highlite/*` importmap keys, `document.highlite`, CSS classes `highlite_titlebar`/`highlite-ui`, localStorage `highlite-console-messages`, the `highlite.dev → ryelite.org` request redirect, and `Copyright (C) 2025 HighLite` GPL headers.
- Renaming productName moved userData from `%AppData%\RyeLite` to `%AppData%\Highspell+`; `src/main/index.ts` copies the old folder once if the new one is missing.
- Main-process IPC handlers (`minimize-window`, `close-window`, `ui-ready`, …) resolve the window with `BrowserWindow.fromWebContents(event.sender)` — **this returns null for a WebContentsView/BrowserView**, so a multi-tab design must route by webContents id instead.
- `app.requestSingleInstanceLock()` + `second-instance` → `createClientWindow()` (second launch opens a 2nd window in the same process).

## Movable HUD (2026-10-11; verified in game 2026-10-12 after the clipping fix)
- `src/renderer/client/helpers/uiLayout.js` (+ `static/css/ui-layout.css`): hold modifier (setting `Interface › Layout Modifier Key`, default Alt) → `#hs-screen-mask` gets `.hsplus-layout-mode`, panels get dashed outline + 4 corner handles. Drag = translate, corner drag = scale about the panel's anchor corner (where the game pins it), modifier+double-click = reset. Only a CSS `transform` is ever set on the game's containers.
- Panels (key → selector, anchor): minimap `#hs-minimap-container` top right, with FOLLOWER `#hs-toggle-minimap-button` (compass `#hs-compass-button` is its own panel since Matt asked) (same transform, scaled about the leader's anchor point via a per-follower transform-origin); logout `#hs-logout-button`; actionbar `#hs-action-bar-menu`; sidebar `#hs-side-action-bar-menu` (all top right); chat `#hs-chat-menu-section-container` bottom left; inventory `#hs-game-menu-container` and menubar `#hs-game-menu-bar-section-container .hs-game-menu-bar` (bottom right, separate so the window and the tab bar move independently — Matt asked for that). Run energy = the sprint item in the action bar(s). Ids came from highspell.com/css/game.12.css (saved copy: `%TEMP%\hsplus-test\game-dom\game.css`).
- Storage: `src/main/modules/uiLayoutStore.ts` → `userData/ui-layout.json` = `{ shared: {panel: {dx,dy,scale}}, accounts: {<character name>: {...}} }` (a legacy flat file is read as `shared`). Setting `Interface › Shared Interface Layout` (default ON) picks the scope: on = `shared` for everyone; off = `accounts[name]` where name comes from `document.title` ("Highspell+ - <name>", set by userHelper at login; falls back to shared before login). IPC `ui-layout:set(scope, panels)`, `ui-layout:get`, `ui-layout:reset` (clears both); `ui-layout:changed` broadcasts the whole store to every window + view. `L()` in uiLayout.js returns the active panel map; a head MutationObserver re-applies when the title (login name) changes. Scale is visual only (bigger minimap ≠ more map); true content resize would need game-internal hooks.
- Events are intercepted in the capture phase with stopImmediatePropagation while the modifier is held, so the game never sees the press as walk/use.
- Resize = MS-Paint style: the grabbed corner stretches, the OPPOSITE corner stays pinned (transform still scales about the anchor corner; `dx/dy` are shifted by `(s0 - s) * lever` where lever = pinned corner − anchor in natural px). All natural geometry comes from `naturalBox()` = offsetLeft/Top/Width/Height + offsetParent rect (layout values, immune to transforms). NEVER measure by clearing the transform: the game's HUD buttons have `transition: … transform .1s !important` (so inline `transition:none` is ignored) and the read comes back mid-animation — that bug compounded to 6.7e7 px origins (the `ui-layout-debug.jsonl` diagnostics that found it were removed 2026-10-12 once the HUD was stable). Verified DOM facts 2026-10-11: minimap, toggle-minimap, compass, logout are all direct SIBLINGS under `#hs-screen-mask` (absolute, CSS right/top), none nested; toggle sits at the minimap's bottom-left (origin (194,-170) relative). The `client.61.js` saved under `%TEMP%\hsplus-test\game-dom` IS the real bundle, just still **gzip-compressed** (the server's response body; `gzip -dc client.61.js > client.dec.js` → 7 MB readable, 173 "minimap" hits). Current version: `curl https://highspell.com:3002/assetsClient` → `data.latestClientVersion`, then `https://highspell.com/js/client/client.<ver>.js`.
- `naturalBounds()` clips each descendant rect to every overflow-clipping ancestor up to the panel (`visibleRect()`, fixed 2026-10-12): `#hs-minimap-container` is `overflow:hidden` around `#hs-minimap__image` + `#hs-minimap__overlay-image`, two divs the size of the whole loaded map region (negative left/top, rotated with the camera), so the frame used to surround the hidden map and corner-resize (baseW/baseH, pinned corner) went haywire — Matt hit it in multibox but it was mode-independent.
- Panel bounds for the outline/handles/resize = `naturalBounds()`: the container's own layout box UNITED with every visible descendant's rect mapped back through the panel transform (`unmapPoint`). Needed because `#hs-game-menu-container` is a near-empty flex box whose menus overflow it (its own box was a tiny yellow square). The outline is a `.hsplus-layout-frame` div in the overlay, not a CSS outline. Scale pivot remains the container's anchor corner; the pinned corner comes from the visible bounds.
- Corner handles live in a fixed `#hsplus-layout-overlay` (not inside the scaled panels) and are repositioned from each panel's bounding rect, so they stay 14 px at any scale. Settings `Interface › Reset Interface Layout` is the new `SettingTypes.BUTTON` field type (renders a button, sends its `action` channel over IPC, no stored value) → `ui-layout:reset` clears the file and broadcasts.

## Perf findings (measured on Matt's PC, 165 Hz monitor)
- FPS: Highspell+ 164 fps (vsync-locked, p99 6.2 ms) vs Chrome 71 fps (12 ms). Electron is NOT slower; Chrome on his machine is. Nothing to fix for FPS.
- RAM was the real complaint. Start: 750 MB / 6 processes. End: ~611 MB / 4 processes; game renderer 586 → 426 MB (Chrome's game tab = 369 MB; Electron fixed overhead main+GPU+net ≈ 185 MB).
- Fixes applied: (1) client.ts no longer acorn-re-parses the whole game bundle on every launch (was `setTimeout 200ms`, "dev testing"), and nulls Reflector.source/ast after parsing → −84 MB heap. Opt back in with `localStorage.setItem('HSPLUS_REPARSE_HOOKS','1')`. (2) Console window created lazily on `show-console` with a 300-msg buffer in main → −1 process. (3) TileMarkers plugin `renderFrame` ran every frame and rebuilt SVG/labels with innerHTML → now early-outs when camera matrix/markers unchanged and reuses pooled elements → −127 MB. (4) Updater `error` handler so packaged builds don't hang without a release repo.
- TCG plugin holds ~30 MB of decoded appearance sheets (`sprites.ts ensureAppearance`); Matt doesn't care about TCG.
- Measuring: `perf/probe.js` (paste in F12 console; game stubs console.log so it draws an on-page box; `window.__probe`), `perf/analyze-profile.js` for .cpuprofile. Per-process RAM: Task Manager → Details → add "Command line" + "Memory" columns (`--type=renderer` / `gpu-process`). Runtime plugin disable does NOT free memory — bisect by restarting. DevTools open = an extra ~150 MB renderer.
- Dev mode (Vite/HMR) is heavier than a packaged build; `npm run build:unpack` for honest numbers.

## Multi-account (built 2026-10-11; smoke-tested: shell boots, 2 accounts in tabs, each loads the game to the login screen; switching/closing/hidden-tab survival/previews NOT yet exercised)
Design mockups: https://claude.ai/artifact/2hQ6pebmy8Pawxkp6hGRVi (side dock / top tabs / collapsed / settings).
- Setting `MultiAccount › Enable Multiple Accounts` (default off, needs restart). Off = the old single-window path, byte-for-byte.
- On: `src/main/windows/shell/index.ts` creates ONE BrowserWindow whose page is `src/renderer/shell.html` (+ `shell/shell.ts`, `static/css/shell.css`) = title bar + account strip/dock. Each account is a `WebContentsView` loading the normal `client.html`; only the active one is `setVisible(true)`. Shell page measures `#content` with a ResizeObserver and sends `shell:content-bounds`; main applies it to every view.
- **All slots share `session.defaultSession` by default** (so installed plugins, cached client, hook map and settings carry over to every tab; the mobile multi build's 6 tabs share one profile and that was device-verified). Setting `Isolate Account Sessions` (restart) puts slots 2–6 in `persist:acct-N` instead. `prepareSession()` replays the highlite.dev redirect + dev headers per session. Matt's first bug report ("no AFK alert on account 2") was almost certainly the isolated partition having none of his plugins.
- Settings added 2026-10-11 evening: `Background Frame Rate` (2/5/15/30/60, default 15 — drives BOTH the hidden-view rAF pump in frameThrottle.js and the dock thumbnail capture rate; previews are JPEG now), `Idle Alert` (+ delay seconds, + optional chime) → `helpers/idleWatch.js` (port of mobile idle-watch.ts; polls `_mainPlayer._currentState`, sends `account:attention 'idle'`; main flashes the tab, clears on activate). `Idle Sound` (Off/Ding/Chime/Bell/Blip/Knock/Idle Alert — ONE master list in `src/renderer/shared/alertSounds.ts`, imported by the client, the settings window (previews via `preview: 'sound'`) AND `plugins/ChatPlus` via `../../../src/renderer/shared/alertSounds`; "Idle Alert" = the Idle Alert plugin's mp3 (GPL-3, CodyBrunson/Idle-Alert) embedded as a data URL in generated `idleAlertSound.ts`, original kept at `static/sounds/idle_alert.mp3`). Tab strips (top/bottom) NEVER collapse; only docks do (title-bar chevron hidden for strips). Layout `multibox` (2026-10-12): every view visible at once, grid computed in main by `multiboxRects(n, contentBounds)` (1 full · 2 halves · 3 = tall left + 2 stacked right · 4 quadrants · 5 = tall third + 2×2 · 6 = 3×2); shell draws no strip/dock, only `#multibox-controls` (+ button, count) in the title bar; a view's `focus` event sets activeSlot so Ctrl+Shift+W (new: close active account) targets the clicked one; main re-applies bounds on the internal `ipcMain.emit('settings:changed')` from settingsManagement. In-view extras for embedded pages (`static/css/multiaccount.css`): `helpers/accountClose.js` prepends a × `.highlite_bar_item` to core's `.highlite_bar` (above Plugin Hub; floats top-right if plugins are off) → `account:close` → `closeAccountOf(wc)`; idleWatch adds `body.hsplus-idle` (full-view translucent tint, Idle-Alert-plugin style, on `#hs-screen-mask::after` in `--hsplus-idle-color` = Idle Alert Color, pulsing 18–38% opacity) when the alert fires (also on the focused account), cleared by a pointerdown in that view or by the character acting + `Idle Sound Volume (%)`; `Idle Alert Color` (new `SettingTypes.COLOR` → native picker + hex box). Settings validation badges now only render when a value is Invalid. The "Restart required" modal only shows when a changed field has `restart: true` in the schema (Release Channel, Enable/Beta Plugins, Enable Multiple Accounts, Isolate Account Sessions); everything else applies live. Changing the layout un-collapses the shell (collapsed strip = hidden, collapsed dock = rail). Collapse: chevron button in the title bar (direction follows layout) and one in the dock header. Top tabs are their own 36 px row UNDER the 28 px title bar (Matt wants the whole title bar draggable). Collapsed dock list: `overflow-x: hidden` + hidden scrollbars (rail buttons overflowed the 56 px dock by 1 px → horizontal scrollbar). Exit crash ("Object has been destroyed" in ShellWindow.destroy): never read `view.webContents` after the window closes — ids are cached on the Account (`wcId`) and every access is guarded. Focus fix: `focusActive()` re-focuses the active view on `did-finish-load` and on every switch (reported: couldn't type into a newly added account's login form) — verified 21:05 by scripted click+SendKeys into account 2's username field after the rebuild. Scripted UI test helpers live in `%TEMP%\hsplus-test\` (`typetest.ps1 <out.png> <x> <y>`, `shot3.ps1` = PrintWindow capture; the scratchpad path is too long for `powershell -File`).
- Views get `backgroundThrottling: false` AND `--hsplus-slot=N` (preload exposes `window.account.embedded/slot`). `client.ts` then installs `helpers/frameThrottle.js` (port of the mobile client's rAF→500 ms timeout pump while hidden) — hidden views get no compositor frames otherwise and the game loop would stall → server drops the session. `titlebarHelpers.js` removes the in-page titlebar when embedded and forwards console warn/error to the shell; `userHelper.js` reports `login` / `ingame` state.
- IPC: `src/main/modules/windowRegistry.ts` (`resolveWindow`, `resolveGameWebContents`) replaces `BrowserWindow.fromWebContents` in windowEventManagement, settings:open, screenshots (screenshot captures the active game view, not the shell page).
- Shortcuts (shell + every view): Ctrl+1…6 switch, Ctrl+` collapse, Ctrl+Shift+T add. Second app launch adds an account instead of a window.
- Live previews: main `capturePage({stayHidden,stayAwake})` on inactive views every 1 s, resized to 240 px, sent as data URL (`shell:preview`). **Unverified** that capturePage returns pixels for a hidden WebContentsView — if it comes back empty, options are: keep inactive views visible but stacked under the active one, or render previews page-side.
- Settings changes broadcast `settings:changed` to all windows + views; shell re-reads layout/previews live. Section-level `note` (warning banner) rendering added to settings.ts.
- Account name comes from `document.title` (`Highspell+ - <name>`, set by userHelper). HP/world/unread-chat in tabs needs game hooks and is NOT done. "Alert on attention" is a CSS class (`attention`) with no producer yet.
- To test: set `"Enable Multiple Accounts"` true in `%AppData%\Highspell+\settings.json` (or via the settings window), restart.
